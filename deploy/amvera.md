# Размещение в Amvera

Приложение запускается как Docker-проект, база — отдельный managed PostgreSQL
в том же регионе. Конфигурация сборки хранится в `amvera.yml` и `Dockerfile`.

## Параметры приложения

- Контейнер слушает порт `3000`, адрес `0.0.0.0`.
- Часовой пояс: `Europe/Moscow`.
- Проверка готовности: `GET /api/health`; успешный ответ содержит
  `{"ok":true,"database":"up","diagVersion":3}`.
- Сборка выполняется без доступа к базе и без секретов.

В разделе «Переменные» проекта задаются:

| Имя | Тип | Значение |
| --- | --- | --- |
| `DATABASE_URL` | Секрет | PostgreSQL URL с внутренним адресом базы Amvera |
| `ADMIN_PASSWORD` | Секрет | Существующий пароль администратора |
| `YANDEX_MAPS_API_KEY` | Секрет | Ключ JavaScript API Яндекс.Карт |
| `SERVER_ACTION_TRUSTED_ORIGINS` | Переменная | Публичное имя сайта, без протокола и пути |

Amvera передаёт переменные только при запуске. Публичный браузерный ключ карт
загружается через `/api/public-config`, поэтому изменение ключа требует
перезапуска приложения, но не пересборки. Этот маршрут возвращает только ключ
JavaScript API; пароли и адрес подключения к базе в ответ не включаются.
В настройках ключа Яндекса при необходимости разрешается новый домен сайта.

## Перенос базы

Перед переносом создаётся полный архив `pg_dump --format=custom --no-owner
--no-acl`. Архив содержит все таблицы, включая `ClientProfileSettings` и историю
миграций Prisma. Восстановление выполняется только в новую пустую базу с помощью
`pg_restore --no-owner --no-acl --exit-on-error`.

Не запускать `db:seed` или `db:copy-to-prod` поверх перенесённых данных: эти
команды предназначены для других сценариев и могут заменить текущие настройки.
После восстановления следует сравнить количество записей во всех таблицах,
проверить `/api/health`, оформление заказа и вход в административную панель.

## Обновления и откат

Обновления кода передаются в репозиторий приложения Amvera или загружаются
архивом без `.env`, `.git`, `node_modules` и локальных файлов других хостингов.
Изменения схемы применяются отдельно через `prisma migrate deploy` до проверки
готовности новой версии. В рабочий контейнер Prisma CLI не включён.

Предыдущую версию приложения можно восстановить через контроль версий Amvera.
Откат кода не откатывает базу данных. Для восстановления данных используется
отдельная резервная копия. В Amvera рекомендуется включить бесплатные ежедневные
резервные копии PostgreSQL.

Приложение остаётся демонстрационным: оформление и состояние оплаты хранятся
в сессии браузера; реальный платёжный шлюз не подключён.

[переменные](https://docs.amvera.ru/applications/configuration/variables.html),
[PostgreSQL](https://docs.amvera.ru/databases/postgreSQL.html).
