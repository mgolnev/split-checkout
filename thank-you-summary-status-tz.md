# ТЗ: thank-you c саммари + упрощённый status

## Задача

Сохранить на `thank-you` ощущение завершённого оформления заказа, но не заставлять тревожного пользователя уходить на отдельный экран за базовой уверенностью.

При этом `/thank-you/status` нужно упростить и превратить из перегруженной служебной страницы в набор коротких повторяющихся блоков по отправлениям.

## Что меняем

### Экран `/thank-you`

#### Что оставить

- success-state;
- заголовок `Спасибо, заказ оформлен`;
- дата и время оформления;
- номер заказа;
- общая сумма;
- короткий статус оплаты.

#### Что добавить

- компактное саммари по каждой посылке прямо в первом блоке;
- каждая посылка показывается одной строкой:
  - `Посылка 1: завтра, 25 апреля`
  - `Посылка 2: завтра, 25 апреля`
- под строкой каждой посылки показать фото товаров с размерами, как в checkout.

#### Что не добавлять

- длинные объясняющие тексты;
- отдельный блок `Что дальше`;
- адрес, получателя, условия хранения, состав отправления, подробные действия.

### Экран `/thank-you/status`

#### Новая логика

Страница должна состоять из простых shipment-блоков.

Один shipment-блок содержит:

- дату доставки / готовности крупно;
- сумму справа;
- короткую вторую строку:
  - `Бесплатная доставка`
  - или `Срок хранения ...`
  - или короткое название источника отправления, если больше нечего показать;
- фото товаров с размерами как в checkout;
- короткую строку оплаты:
  - `Оплата при получении`
  - или `Оплачено онлайн`
- две кнопки:
  - слева `Отменить` как третьестепенная по UI kit;
  - справа `Оплатить сразу` как второстепенная.

#### Если отправлений несколько

- блоки повторяются по числу отправлений;
- вверху можно показать короткое общее summary:
  - количество отправлений;
  - номер заказа;
  - общую сумму.

#### Внизу страницы

- только summary всех отправлений / итог по заказу.

## Что удалить со status

- длинные информеры;
- отдельный блок помощи;
- отдельный блок получателя и адреса;
- раскрывающийся `Состав отправления`;
- отдельную кнопку `Подробнее`;
- тяжёлые текстовые пояснения;
- длинные служебные формулировки.

## Контентные правила

- Тексты короткие и предметные.
- Не писать канцелярские фразы вроде `Покажем точную информацию`.
- Не писать длинные инструкции.
- Один блок должен читаться за один взгляд.

## Критерии приёмки

- На `thank-you` пользователь сразу видит summary по каждой посылке и фото товаров с размерами.
- Для базового успокоения не нужно переходить на `/thank-you/status`.
- `/thank-you/status` читается как список простых карточек отправлений, а не как длинная ведомость.
- В каждой карточке есть только ключевое: когда, сколько, что внутри, как оплачивается, что можно сделать.
- Внизу есть общий итог по заказу.
